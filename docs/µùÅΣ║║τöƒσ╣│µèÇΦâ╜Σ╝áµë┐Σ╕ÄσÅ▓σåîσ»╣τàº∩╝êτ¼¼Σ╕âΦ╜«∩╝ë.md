# 族人生平、技能、传承与史册对照（第七轮）

> 日期 2026-11-06。对应 `wqn.html` / `wqn.htm`（约 3.1 MB，离线单文件）。
> 缘起：「增加可以看生平，族谱，族人技能，传承，是不是历史名人等」。

---

## 一、先说最重要的一句

**本局族人一律是推演生成的人物，不是历史名人。**

这句不只是写在免责里，而是做成了游戏里的硬判定：任何族人卡都固定显示
「不是历史名人 · 本局推演族人」，即使把族人改名成「孔子」也一样。
因为把随机生成的族人写成某位真实人物、或说成「某某之后」，是最容易失真的地方。

所以「是不是历史名人」拆成了两件可玩的事：

- **同名用字检索**：拿族人姓名的用字去比对册中 37 位人物条目与 12 位人物生平，
  命中的只写「姓名用字含某字」，**不写身份认定**；附一句
  「同名只是用字巧合；本局族人不等于册中任何历史人物，不与任何真实家族攀附血缘」。
- **史册对照**（族谱页末单独一栏）：这里才是真正遇见的史实人物，
  只收本局 `seenCiv` 里「人物」维度的条目；有生平四段的显示
  生卒／时代、事迹、身后影响与出处。两栏明确分开，不混写。

## 二、族人卡：点开每个人看四件事

族谱页现在每位在籍族人（外加最近两位故去的族长）各有一张可点开的卡：

**① 生平 · 推演小传**
第几代、约某年生、在籍年岁或享年、按当时条件估的寿数、性情、
是否当家／继承人、落脚地、亲习之业、承袭之业、编年里提到此人的近事、
亲历的抉择（何年习何业）、承自何人、名下子嗣、继立记录、了结的旧账。
全为推演，明确写「由本局抉择写回，不是史实履历」。

**② 族人技能**
「族中业」以前只是族级计数（`S.jobs`），现在每次抉择会把技能**落到具体某人身上**：
`recordSkill` 一半落在当家、一半按年份派生给其他在籍者，写进 `p.skills` 与 `S.skillLog`。
卡上分两色：

- **亲习**：由抉择写回，可追溯到哪一笔
- **承袭**：父辈有业时按 id 派生 1—2 条，明确「只表示族里有人做过，不代表本人亲习」

**③ 传承**
新生儿记 `parent` 指针与 `fromName`；卡上列出承自谁（第几代）、
承自内容（本族称法、落脚地、性情、父辈之业）、名下子嗣与在籍人数、
继立类型（嫡长／兄终弟及／旁支过继／绝嗣立新）、由本人了结的族谱旧账。
清账时也会记下 `clearedBy`，所以「谁收拾了上一代的账」能查。

**④ 是不是历史名人**
固定结论 + 同名用字检索结果 + 免责声明，如上。

页顶加了一行汇总：在册 N 人（在籍 X · 累计凋零 Y）/ 若干代 ·
亲习技能 K 项 · 抉择记入生平 M 笔 · 有父辈可考 P 人 · 遇真实人物 R 位。
收卷报告也多了「本局族人 / 亲习技能 / 遇真实人物」三格。

## 三、顺手修了一个长局真 bug

做传承时发现 `S.fam` 会无限累积：**40 笔堆到 175 人，在籍只剩 1–2 人**。
原因是裁剪只在「在籍 >14」时触发，故去者从不清理；而远古一笔跨百余年、
按 25 年切成 8 小段，凋零远快于出生，族谱几乎读不出东西。

三处修法（全在 `family.js`，不改寿数模型与编年跨年）：

1. **每小段至少候补 1 名新生儿**，成行概率略抬；在籍上限与 `birthBudget` 仍卡着。
2. **每笔末保底补到 4 位在籍**，仍归下一代、仍记父辈指针。
3. **故去者只留在籍者的父辈链两层 + 最近两位故去族长**，其余移出在册；
   父辈已不在册时，传承卡显示「承自某人 · 已不在册，仅存其名」，链不断。

修后同口径 40 笔：**在籍 4 人、在册 8 人**，族谱页有 4 张在籍卡 + 2 张故去族长卡。
汇总里的「代」改以游戏在册的 `S.gen` 为准，不再因裁剪误显示「1 代」。

## 四、确定性没被破坏

新模块 `src/people.js` 是纯逻辑、无 DOM，**不调用主 `rnd()`**：
承袭、性情继承、技能归属全从 `person.id` 派生哈希。专项断言确认
调用 `bioOf` / `historyCheck` 前后 `rngState` 逐字一致，
同 seed + 同选择序列仍逐笔一致，旧存档直接刷新续上（缺字段就地兜底）。

家族出生率调整确实改变了新局的随机序列，但那是版本内一致的新基线；
分享串复盘、旧档迁移、三档难度、真实性档位全部回归通过。

## 五、验证

三套测试全绿、零报错，浏览器流程连续多轮稳定通过。新增专项：

- 技能写回落到个人、去重、承袭与亲习不混同、生平段落只读且 `rngState` 不变。
- 40 笔长局后父辈指针有效、承自内容非空、史册对照只收「人物」维度且带生平四段、汇总统计合理。
- 常规族人与「强行改名孔子」的族人都判定为**不是历史名人**，同名理由只写用字重合。
- 浏览器：族谱页「不是历史名人 / 推演小传 / 族人技能 / 传承 / 史册对照 / 两下分栏」
  六项文案齐全，点开卡能读到内容，收卷报告汇总格存在。
- 族谱页 render 约 **11.4 ms / 761 节点**（390×844 手机视口）。

## 六、还能往哪走

1. **故去者归档册**：现在只留父辈链两层，可给每位故去者一份「卒年、享年、一生亲习之业、
   子嗣」的归档，不进在册但能翻。

   直接改变该类选项的收益与失手率。
3. **人物生平扩展**：12 位有完整四段生平，其余 25 位人物条目只有梗概，可逐位补。
4. **逐条升级出处**（仍是第一优先的内容债）：1174 条姓氏、33 条人群、283 条术语锚点
   仍为域名级入口 + 引文留空。
