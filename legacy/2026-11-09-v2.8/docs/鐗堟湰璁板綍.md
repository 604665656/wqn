## 递增规则

版本号存在 `data/version.json`，由 **`pending` 驱动**，`node build.js` 自动消费：

1. 每轮开始，往 `version.json` 写一个 `pending`（标题 + 本轮条目）。
2. 第一次 `build.js` 读到 `pending`：
   - 首轮建立基线（v1.0，不递增）；之后每轮 **minor +0.1**（v1.1、v1.2…）、`build +1`
   - 日期取当天，把 pending 写进 `changelog` 顶部，然后清空 `pending`
3. 同一轮里反复 build（测试、改一行再打包）**不会再递增**，因为 `pending` 已空。
4. 只有重大重构才手工把主版本 +1.0。

界面三处可见：开局页底部、设置页「这一局」、收卷报告页脚；`<title>` 与
HTML 头注释也带版本；存档 `S.ver` 由 `fresh` 写入，旧档 `migrate` 自动补。

**版本号只标识这一份可玩文件**，不是史实纪年、不改任何条目、不影响旧存档续玩。
源码包里 `tools/bump_version.py` 可作为手动写 pending 的辅助（可选）。

## 下一轮怎么加

只需在 `data/version.json` 里写：

```json
"pending": {
  "title": "v1.1 · 这一轮做了什么",
  "items": ["条目一", "条目二"]
}
```

然后正常改内容、`node build.js`。版本号、构建号、日期、changelog 会自动落好，
界面与存档同步显示。不用再提醒。
