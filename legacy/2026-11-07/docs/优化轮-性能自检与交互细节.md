# 优化轮：体积、首屏、渲染、自检与交互细节

> 日期 2026-11-06。对应 `wqn.html` / `wqn.htm`（**3.0 MB**，离线单文件）。
> 缘起：上一轮把姓氏扩到 1295 条、文明条目 1589 条后，文件涨到 3.9 MB。
> 这轮不堆内容，只治「变大之后带来的问题」。

---

## 一、体积：3.9 MB → 3.0 MB

查出 main 因：1174 条新增姓氏共用同一段 boundary，2590 个 `sources[].note`
共用同一句「域名级检索入口…」；这些长串在 `JSON.stringify` 后被逐条原样写进 HTML。

**构建期字符串池**（`tools/pool.js`）：

- 长度 ≥16 且出现 ≥2 次的字符串抽进池，原位置换成 `\u0001<索引>\u0001`
- 运行时在所有模块读 `WQN.data` **之前**递归还原
- 只池化字符串原始类型，不做对象引用共享，避免「某处改名串改全局」
- 占位符经 JSON 转义后是 ASCII 序列，`<script>` 内无真实控制字符

结果：**2026 项池 / 17941 处引用，净省 472.8 KB**，文件 3976.7 → **3080.8 KB**。

---

## 二、数据完整性自检：被下载器改坏时给人话，不白屏

- 内嵌 `__WQN_CHECK__`（原始 JSON 的 FNV-1a 与长度）
- 默认轻量抽样：主体数据存在、条目数达标、最后一条姓氏的 boundary 已还原、
  还原后 JSON 长度与构建时一致
- `?verify=1` 做**完整逐字符校验和**（默认不跑，省首屏）
- 任一环节失败 → 页面直接显示「数据没能完整展开：…请重新下载并用浏览器打开」，
  `main.js` 停止启动
- 实测默认与 `?verify=1` 都 `{"ok":true,"n":2352249,"full":true}`，零报错

这条专门治你最早遇到的「下载了打不开」：现在至少能明确告诉你是文件坏了还是打开方式不对。

## 三、渲染：游戏页 40.5 ms → 6.9 ms

| 优化 | 效果 |
| --- | --- |
| 静态片段缓存 `cacheHTML` | 深读全册／264 道判读／姓氏各组只拼一次，按「已答日志版本」失效 |
| **按页签生成** | 1295 条姓氏与 264 道题只在 TAB=`文明` 时生成；主推演页不再背着上千节点 |
| 全部姓氏／人群／边界组懒加载 | 文明页可见节点 3030 → **1180**，初始可见行 0（都在 template 里） |
| 维度索引 `dimIdx` | 不再每次 `find` 90 维数组 |
| **记住展开过的组** | `LAZYOPEN` 让切页签、重渲染后自动恢复展开状态，不再「点开又合上」 |

实测（390×844 手机视口，Chromium）：

- 主推演页 render **6.9 ms / 734 节点**
- 文明页 render 约 50 ms / 1180 节点（仅切到该页签时）
- 首屏 load 约 0.7 s（含 3 MB 解析 + 池还原 + 轻量自检）

## 四、检索：1295 条全匹配不再糊满屏

输入关键词后原本会一次显示上千行。现在：

- 全量载入后**只露前 60 条**，写明「匹配 N 条 · 显示前 60 条（换个关键词可继续筛）」
- 条目一条没删，清空检索仍按组逐条翻
- 浏览器断言确认：可见 1—60 条、全部命中关键词、计数提示存在

## 五、交互细节：两个「后果没活着」的地方

**族账跨代**：组合技失手挂的旧账，以前同一代就能立刻清掉。现在记下产生时的 `S.gen`，
只有**下一代当家之后**（或久远 150 年兜底，避免短局永不换代）才出现「清旧账」。
测试专门断言「同代不出、换代才出、清完不再重出」。

**卷末汇流补口径**：卷末回响以前只看八维与行当，现在会写进

> 这一卷辨了 3 处读法（稳妥 1／折中 1／误取 1）；…族谱上还挂着 1 笔旧账，得等下一代人来收拾。已有 2 笔旧账了结。

判读倾向、未了旧账与已了旧账都进汇流，既有汇流字段一个没动。

## 六、边界纪律

1. **零内容改动**：1589 条文明条目、1295 条姓氏、264 道判读、106 则深读、
   174 条地方史、全部史事与出处逐字未改。本轮只动构建、渲染、缓存、自检与回响措辞。
2. **压缩可逆**：字符串池只作用于构建产物，源工程 `data/*.json` 仍是完整可读 JSON；
   `?verify=1` 可逐字符证明还原无丢失。
3. **不改史实、不改确定性**：自检与缓存都是只读；`cacheHTML` 的失效键只依赖 `readingLog`，
   不碰随机状态；同 seed + 同选择序列仍逐笔一致。
4. 难度／真实性档位／玩法／时长／史料密度、舆图缩放、导出、存档全部不受影响。

## 八、还能往哪走

1. **文明页 50 ms**：瓶颈在 1180 个 template 节点的 HTML 解析，可改成「点开时用 JS 从 data 现拼」，
   初始 HTML 里完全不放 template 内容；会进一步降到 ~10 ms，但要改懒加载协议。
2. **首屏 0.7 s**：3 MB 单文件的固有成本；外置 JSON 按需 fetch 会快，但牺牲「离线单文件」。
3. **逐条升级出处**（仍是第一优先的内容债）：1174 条姓氏、33 条人群、283 条术语锚点
   仍为域名级入口 + 引文留空。
4. **收卷长图**：3 MB 页面导出 PNG 在极低端机可能慢，可改分块绘制。
